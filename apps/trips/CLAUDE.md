# Vylo — органайзер поездок с автодневником

> **Статус: Этапы 1–3 готовы** (ядро, расходы, карта и дневник) — MVP для проверки гипотезы собран. Дальше: выкладка на https-хостинг, показ людям, измерение «делятся / не делятся» (см. «Принятые решения»).

## Что это и какую гипотезу проверяем
Приложение для путешественников. Главная гипотеза первой версии: людям нравится **автоматически собранный
красивый дневник поездки**, и они **делятся им в соцсетях**. Всё остальное (поездки, маршрут, документы,
расходы, карта) нужно, чтобы дневнику было из чего собираться.

## Жёсткие ограничения (не нарушать)
- **Никакого ИИ/LLM** в приложении. «Умное» — только алгоритмы, шаблоны и правила.
- **Никакого бэкенда, аккаунтов, серверов.** Всё на устройстве (local-first).
- **Полностью офлайн.** После первой загрузки приложение работает без сети; сеть нужна максимум для необязательного
  кэша курсов валют (Этап 2).
- **Данные и документы остаются на устройстве** и никуда не отправляются. Нет аналитики и трекеров внутри приложения.
- **Минимум платного и минимум зависимостей.** Каждую новую зависимость обосновывать (размер, лицензия, нужна ли).
- **Не добавлять функции вне списка без вопроса.** Особенно: друзья, соревнования, аккаунты, импорт из почты, ИИ,
  уведомления, общие поездки.

## Принятые решения
- PWA на React + TypeScript + Vite (не Expo): бесплатно, один код для телефона и веба, ссылка вместо магазина.
- Приложение живёт в `apps/trips`; существующее приложение `apps/vylo` (Next.js) не затрагивается.
- Интерфейс только на русском; все тексты в `src/core/strings.ts` (добавить язык — повторить объект).
- Города и координаты офлайн: встроенный список городов с населением от 15 000 (GeoNames `cities15000`, CC BY 4.0 — подпись в
  «Настройках → Источники данных»), лежит отдельным ленивым куском `data/cities.generated.json` (≈ 1,4 МБ, грузится при первом
  выборе города); русские названия (до 8 на город) — для поиска. Собирается `scripts/build-geo.mjs`. Мелкие города (< 15 тыс.)
  в списке нет: их можно ввести текстом, но на карту и в километры они не попадут (можно задать свои координаты).
- Карта (Этап 3): офлайн-мир, границы стран из `world-atlas` (Natural Earth, 50m, общественное достояние), рисуется самим
  приложением (SVG на экране, Canvas для картинок), без тайлов и без MapLibre. Детальные карты улиц (PMTiles) — отдельным
  решением позже, если понадобятся.
- Счётчики карты: страны — поездок, которые уже начались (`startDate <= сегодня`); будущие — отдельным цветом «в планах».
  Города — уникальные города поездок и записей. **Километры — по прямой вдоль маршрута внутри поездок.** Необязательный
  «домашний город» (Настройки → `settings.homeCity`, выбирается из встроенного списка, лежит только на устройстве и входит в
  копию): тогда к каждой начавшейся поездке добавляется прямая от дома до первой точки маршрута и от последней обратно
  (`stats.ts`, поле `homeKm`); без него перелёты из дома не считаются. Поездка без найденных координат дорогу не добавляет.
  В дневнике «км» остаются внутри поездки (фраза «между остановками»), дорога из дома — только на карте и итоговой карточке.
- Дневник (Этап 3): без ИИ, из данных поездки (`modules/diary/generate.ts`): шаблонные фразы с подстановкой + случайный выбор
  по зерну (`random.ts`, mulberry32), чтобы повторы не лезли в глаза (`Picker` не берёт один шаблон дважды подряд). Страницы:
  обложка, обзор, дни, факты/рекорды, карта маршрута, финал. Тексты хранятся в базе (`diaries`), поэтому правки пользователя и
  порядок страниц не теряются; «Пересобрать» сливает свежую генерацию со старой по ключу страницы (`merge.ts`: сохраняются
  правки текста, скрытые страницы, порядок, замены фото). Признак «данные поездки изменились» — отпечаток (`fingerprint`).
- Русские фразы: город/место только в именительном падеже после двоеточия/тире/в кавычках (склонять нельзя), числительные —
  через `plural()`, нет глаголов прошедшего времени от первого лица (род пользователя неизвестен).
- Стили дневника: `minimal` (Inter), `magazine` (Playfair Display), `postcard` (Caveat + IBM Plex Mono) — у каждого свои цвета,
  шрифты и раскладка (`render/themes.ts`, `render/pages.ts`). Шрифты — локальные (`@fontsource`, `?url`, подгружаются через
  `FontFace`, уходят в офлайн-кэш).
- Рисование страниц — Canvas в «условных единицах» (`render/pages.ts`): одни функции для страницы А5 (1240×1754), stories
  (1080×1920) и квадрата (1080×1080). Фото кадрируются (`focus` + приближение), замена фото пользователя хранится как
  отдельная запись `photos` без `itemId`; лишние удаляются (`dropUnusedUserPhotos`).
- PDF: собственный минимальный писатель (`pdf.ts`) — каждая страница это JPEG-картинка на странице А5 (jsPDF не взяли из-за
  размера и лишних зависимостей). Минус: текст в PDF нельзя выделить/скопировать — сказано в окне экспорта.
- Итоговая карточка «N стран, N городов, N км» (`render/yearCard.ts`, окно `map/ShareCardSheet.tsx`): за год или за всё время,
  три стиля, stories и квадрат; подпись «Сделано в Vylo» внизу каждого файла.
- Резервная копия: один файл `.vylo` (zip), необязательно шифруется паролем; **восстановление заменяет все данные**.
- В дневнике (Этап 3) пользователь может заменить любое фото своим: из галереи/камеры, с кадрированием, с кнопкой
  «Вернуть оригинал»; замена попадает в PDF и картинки.
- Курсы валют (Этап 2): при интернете приложение само подгружает их и кэширует с датой (`modules/expenses/rates.ts`).
  Источники по очереди: open.er-api.com → cdn.jsdelivr.net (currency-api) → currency-api.pages.dev → api.frankfurter.dev (ЕЦБ);
  ответ строго проверяется, при отказе берётся следующий. Обновление — если сохранённым курсам больше 12 часов: при запуске,
  при появлении сети, при возвращении в приложение; после неудачи пауза 15 минут (кроме момента появления сети). В сеть уходит
  только запрос курсов, без данных пользователя (`credentials: 'omit'`, без referrer). Автозагрузку можно выключить.
  Свои курсы пар (`manualRates`, ключ `ТНВ>EUR`) важнее автоматических. Нужна ссылка на ExchangeRate-API (есть в «Курсах»).
- Расходы: итоги в валюте отчётов поездки (`trip.currency`, по умолчанию «домашняя» — последняя выбранная или по языку
  телефона). Валюта новой траты по умолчанию — последняя использованная в поездке, иначе валюта страны. Траты без курса не
  входят в итог и выделяются. Средний расход в день считается по тратам внутри дат поездки.
- CSV: разделитель `;`, дробная часть запятой, UTF-8 с BOM (для русского Excel), экранирование формул (`=+-@`).
- Имена скачиваемых файлов — латиницей (транслит), см. `core/files.ts`.
- Как измерять гипотезу «делятся»: ссылка в подписи «Сделано в Vylo» на отдельную страницу с бесплатным счётчиком без
  cookie — **не в приложении**, решить перед запуском.

## Стек
React 19, TypeScript, Vite 8, **Dexie** (IndexedDB), **react-router** (HashRouter — не требует настройки сервера),
**dnd-kit** (перетаскивание), **vite-plugin-pwa** (офлайн, service worker), **fflate** (zip для копии),
**Web Crypto** (AES-GCM + PBKDF2 для PIN и пароля копии), **Vitest** + **fake-indexeddb**, шрифты через `@fontsource`.
Этап 3: **d3-geo** + **topojson-client** + **world-atlas** (карта), собственный писатель PDF, Canvas (картинки). Для сборки
данных (не попадают в приложение): `cities-15000-structured`, `i18n-iso-countries`.

## Команды (из корня репозитория)
```
pnpm install
pnpm --filter @vylo/trips dev        # разработка: http://localhost:5173 (обновляется на лету)
pnpm --filter @vylo/trips build      # проверка типов + сборка в apps/trips/dist
pnpm --filter @vylo/trips preview    # сборка как у пользователя: http://localhost:4173 (тут работает офлайн-режим)
pnpm --filter @vylo/trips test       # тесты
pnpm --filter @vylo/trips typecheck
```
Важно: шифрование документов и service worker работают только на **https** или **localhost**. По обычному
`http://192.168…` с телефона PIN/документы и офлайн недоступны — для проверки на телефоне нужен https-хостинг
(Cloudflare Pages, Netlify, GitHub Pages — бесплатно) или тоннель.

## Данные и модель
- Даты — строки `ГГГГ-ММ-ДД` в местной зоне. Порядок записей в дне задаёт `order`, время — подпись; запись со
  временем сама встаёт по времени, перетаскивание меняет только порядок.
- Документы: в базе только шифртекст (имя/тип и содержимое отдельно). Ключ документов (DEK) обёрнут ключом из PIN;
  смена PIN перешифровывает только DEK. PIN ≥ 6 символов. Забытый PIN не восстановить (есть «сброс»: удаляет документы).
- Любое изменение схемы базы — новая `db.version(n)` в `core/db.ts`, чтобы не потерять данные пользователей.
- Версия формата копии — `BACKUP_VERSION` в `core/backup.ts` (сейчас 3: с расходами и дневниками; копии версий 1–2 читаются);
  более новый файл старое приложение отвергает. Кэш курсов (`settings.rates`) в копию не входит, свои курсы — входят.
- Ключи настроек: `vault`, `rates`, `manualRates`, `ratesAuto`, `homeCurrency`, `homeCity`, `lastCurrency:<tripId>`.

## План этапов
1. **Ядро** — ГОТОВО.
2. **Простые расходы** — ГОТОВО (ввод за 3 касания, итоги по дням/категориям, средний расход, бюджет с остатком,
   курсы с автозагрузкой и ручным вводом, CSV, расходы в резервной копии).
3. **Карта и дневник** (главное) — ГОТОВО: карта посещённых стран/городов, счётчики, дневник в 3 стилях без ИИ, правка текста
   и порядка, замена фото, экспорт PDF и картинок (stories 9:16, квадрат 1:1) с подписью «Сделано в Vylo», итоговая
   карточка «N стран, N городов, N км», тесты генератора.
Дальше (вне списка, только после вопроса владельцу): ссылка и
счётчик для измерения «делятся»; детальные карты улиц (PMTiles); печатные версии дневника.

## Правила работы
- Этапами; после каждого — коммит в git с понятным сообщением и отчёт: что готово, как запустить, что проверить
  вручную, что дальше.
- Код понятный, с короткими комментариями; модули независимы.
- Развилка или неясность — вопрос, а не догадка. Владелец — новичок: объяснять простыми словами.
- Русские фразы дневника: город только в именительном падеже (склонять названия нельзя), числительные — через
  `plural()` из `core/strings.ts`.

## Известные ограничения Этапа 3
- Города берутся из списка (≥ 15 тыс. жителей); деревни и мелкие города на карте и в километрах отсутствуют, пока не задан
  свои координаты у места. Места без координат и без города в километры не входят.
- Километры — по прямой, не по дорогам; дорога из дома и обратно считается только если задан домашний город (поездка = «туда и обратно» одной прямой в каждую сторону, пересадки не учитываются).
- Страница дневника в PDF — картинка (текст не выделяется). Фото в экспорте уменьшаются до размеров страницы.
- Тексты дневника — шаблоны: при очень маленьком числе данных (1–2 записи) дневник получается коротким. Это честное
  поведение, а не ошибка; «Другие формулировки» перемешивает шаблоны, но смысл не выдумывает.
- Шрифты и карта весят: первая загрузка ≈ 3,4 МБ (кэшируется, дальше офлайн). Список городов грузится только при первом
  выборе города.
- Заметки записей маршрута выводятся в дневнике как есть (в одну строку, с многоточием) — их содержание не обрабатывается.

## Известные ограничения Этапа 2
- Живые ответы сервисов курсов при разработке проверить не удалось (из среды разработки они недоступны): форматы
  разобраны по документации и покрыты тестами на образцах; проверять на реальном интернете.
- Курсы справочные (не банковские); значение пересчитывается по текущему курсу, а не «замораживается» на день траты.
  Если важен реальный курс обмена — задайте свой курс пары вручную.
- Деление трат между попутчиками в список этапов не входит.

## Известные ограничения Этапа 1
- Резервная копия собирается в памяти: очень большие объёмы фото/документов (сотни МБ) могут быть тяжёлыми для слабых
  телефонов.
- Браузер может очистить данные при нехватке места (особенно на iPhone). Приложение просит «постоянное хранилище»
  при добавлении документа, но гарантий нет — поэтому нужны копии.
- Короткий PIN слабо защищает от того, у кого есть сами файлы базы: рекомендуем длиннее 6 символов с буквами.
- Перетаскивание — за значок-«ручку» справа; между днями работает, во время перетаскивания страница автоматически
  прокручивается.
